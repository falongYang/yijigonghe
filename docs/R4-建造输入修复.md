# R4 建造输入与反馈修复

2026-11-15；基于108f94c；未部署。

## 用户反馈与定位

群主报告 Mac 触控板单击、点击释放无法建兵营，并反馈没有建造模式/落地反应。尚未直接操作其物理触控板。

本地 Chrome 1440×960 真浏览器点击发现两个独立错误：

1. touch.js 的 isSyntheticMouse / isTouchActive 默认参数写为 defaultNow()，得到数字后又执行 now()，在画布 mousedown / mousemove 时抛出 TypeError，事件处理中断。测试过去只注入函数时钟，没有覆盖生产默认调用。修为默认传入 defaultNow 函数，增加默认调用回归。该错误影响鼠标事件路径，包含触控板模拟鼠标，不是拖拽阈值问题。
2. ui.js 建造按钮悬停造价提示读取 this.era.P，但 UI 没有 era 字段，改为 this.sim.era.P。此悬停错误独立于画布输入错误；本地按钮本身原先仍可进入建造模式，所以不能声称已复现用户所有症状。

## 体验反馈

- 建造按钮按 pendingBuild 高亮，并提供 aria-pressed 状态；取消或落地后恢复。
- 选建筑后显示建造操作提示。
- 地面射线为空时明确提示“未选中地面”，保留建造意图，避免静默失败。
- 不改变鼠标按下时放置的既有时序，不修改模拟规则或拖拽阈值。

## 验证

- node run-tests.mjs：完整回归通过，包括新增默认时钟调用。
- browser-build-smoke.mjs：Chrome 软件 WebGL，1440×960，实际鼠标事件通过悬停提示、点击进入、高亮、Esc取消、模拟空地面射线后的提示与意图保留、有效地面点击创建实体与扣费。
- 实测兵营0→1，生物质340→160，pendingBuild清空，页面运行错误0。
- 空射线分支为测试注入，不能当作实机地平线点击复现。
- 未验证物理 Mac 触控板，未验证用户所打开的线上版本，未部署。只能记“已修复确定的鼠标输入代码错误，待触控板实机复验”，不能标整个用户问题验收完成；R4其余待办不变。

复现命令：启动本地静态服务，再设置 PLAYWRIGHT_MODULE、CHROME_EXECUTABLE、GAME_URL，运行 node browser-build-smoke.mjs。Playwright为外置测试依赖，不引入运行时依赖。
