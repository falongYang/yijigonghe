# 窄屏点选修复及操作链验证

实现：pickEntity 新增可选的单位容差。保留所有原有可见实体射线命中；只有射线未命中才在屏幕空间寻找最近的己方可见单位身体中心，触屏24 CSS像素、鼠标12 CSS像素。排除屏幕外与近远裁剪面外单位。仅 pickAt 点选传入容差，攻击、维修等 commandAt 调用保持精确拾取。已有射线命中邻居时不改变目标，因此不承诺解决所有扎堆选错问题。

## 验证

- bun run-tests.mjs 全部源码语法及既有行为回归通过；git diff --check 通过。

- 实际屏幕tap选工蚁→正常tick采集入库→点兵营→取消且未扣费→重新点兵营及合法地面→正常tick建成→屏幕tap选兵营→点生产兵蚁→正常tick产出→屏幕tap选新兵→Chrome输入通道长按合法地面下令→教学完成。无 selected 集合写入、无直接调用 produce、无资源/单位注入。

## 复现方法与边界

旧探索脚本聚焦后等待250ms仍可能处于相机过渡，实测点击前后中心相差约29px；增加至2000ms后点选成功。因此此前失败包含相机夹具干扰，不能全部归因于热区。

本脚本以渲染身体中心确定点选坐标，不以pickEntity反向筛选像素；使用相机聚焦夹具、game.speed=0暂停自动推进，并用正常sim.tick加速等待。通过证明上述条件下的屏幕操作链及容差恢复漏选，不证明持续移动/密集扎堆下的成功率、玩家自主导航或物理触屏硬件体验。

复跑：MVP_Web服务在8000端口；设置PLAYWRIGHT_MODULE为本机playwright或playwright-core模块入口后执行bun browser-selection-chain.mjs。
